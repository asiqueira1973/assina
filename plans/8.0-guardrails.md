## Como se prova
`./scripts/test-guardrails.sh` monta o JSON que o Claude Code entrega ao hook (Write com `file_path` e `content`) e confere o código de saída de cada caso: 2 bloqueia, 0 libera. `guard-migrations` e `guard-tests` rodam num repositório git temporário, com uma migration commitada e o arquivo `.claude/fix-mode`.

| Critério do 8.0 | Casos |
|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` ou `SELO_P12_BASE64` em página pública é bloqueado | guard-secrets 1–2 (e mais R2, `NEXT_PUBLIC_*KEY` e `use client` importando `src/server`) |
| `.from('as_eventos').update(`/`.delete(` bloqueado | guard-audit 1–4 (inclusive quebrado em linhas) |
| Migration commitada não se edita | guard-migrations 1 |
| Com `.claude/fix-mode`, editar teste é bloqueado | guard-tests 2–3 |
| Migration dispara o lembrete de advisors | remind-advisors 1 |
| "certificado digital" ou "ICP-Brasil" na copy é bloqueado | guard-copy 1–3 |

Cada hook tem também pelo menos um caso que **deve passar**, para pegar hook que bloqueia demais.

## Divergências do spec (Anexo B já atualizado no mesmo commit)
1. **`guard-audit.sh`** lia linha a linha e não pegava `.from('as_eventos')` e `.update(` em linhas separadas, que é o formato do Prettier. Agora junta as linhas antes do grep.
2. **`guard-copy.sh`** usava `100% v[aá]lid`. No grep do macOS o colchete compara byte a byte e "á" tem dois bytes, então "100% válida" passava. Trocado por `100% v(a|á)lid`. O teste pegou isso na primeira execução.

## Fora do alcance deste teste
Os hooks só rodam numa sessão do Claude Code aberta **em `~/assina`**. Esta sessão foi aberta em outro projeto, então o teste chamou os scripts diretamente. A prova de integração (o Claude Code tentar um Write proibido e ser barrado) fica para a primeira sessão em `~/assina`: rode `./scripts/test-guardrails.sh` e peça uma edição proibida uma vez.
